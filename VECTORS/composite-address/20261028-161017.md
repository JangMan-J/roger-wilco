## Position

The two Reference fields are opaque **base-36 tokens** (lowercase `0-9a-z`, no leading zeros, zero written `0`, any length), not integers (Jang, 2026-10-29). Roger names no meaning for either: rank, project and spawn sequence are gone from its glossary, KERNEL proof 6, README and usage text; whoever composes an Address decides what the tokens mean (Jing: left rank, right project number). Glossary term "Opaque integer" is now "Opaque token"; frozen text edited in place and re-pinned.

A Roger **code change was needed, in the Pi shim only**: `roger-env.ts` (`ROGER_ADDRESS_PREFIX` validation) and `roger-target.ts` (composite recognition) required decimal `\d+`, so a token such as `zz` or `1a` was refused as a prefix and a typed composite fell through to label matching. Both now share one `TOKEN` grammar. The Rust core, Board, coordinator and claude shim needed nothing; none of them parses a Reference. Nothing case-folds an Address: the shim's `fold` is for label and prefix comparison only, and the composite is now matched case-sensitively and routed exactly as typed.
